# ADR-035: API docs written by Scribe, served by CourtKu at /docs

- **Status:** Accepted
- **Date:** 2026-11-14

## Context

The plan (section 14) asks for "API documentation generated by Scribe and published at /docs on the API host". The API sends a strict content rule with every answer (`default-src 'none'`, docs/security.md), which a documentation page with its own styles and scripts can't work under. The live image is built without development packages (`composer install --no-dev`).

## Decision

- **Scribe is a development tool** (`require-dev`). `composer docs` (in `apps/api`) writes the page to `resources/views/scribe/index.blade.php`, its styles and scripts to `public/vendor/scribe/`, and the Postman collection and OpenAPI file to `resources/docs/`. All of these are committed, so the live server needs no Scribe; `config/scribe.php` returns nothing when Scribe isn't installed.
- **CourtKu serves the docs itself** (`DocsController`, `routes/web.php`): `/docs`, `/docs.postman` and `/docs.openapi`, without a session, so they open even when the database is off. The docs page sends its own content rule, which allows its scripts and styles (and the few it loads from public CDNs) but still no framing, forms or plugins. Every other answer keeps the strict rule.
- **What the docs show:** every public, player, staff, owner and admin endpoint, grouped (`@group` on each controller), with the fields taken from the validation rules, real-looking examples for addresses (`arena-demo`, `CK-7F3K2`) and a "requires authentication" badge where a login is needed. The introduction explains the session-cookie login, the error shape, times and money. The base address is the web app, which forwards API calls (ADR-004). Internal routes (the cron tick, the admin's test error, the browser tests' pretend Stripe) are left out.
- **No calls to a running API while writing the docs** (Scribe's "response calls" are removed): the docs never depend on, or change, what is in a local database. "Try it out" is off, since the API only takes requests forwarded by the web app (ADR-025).
- CI's "API Docker image" job checks that `/docs` answers 200 from the production image with the database down.

## Alternatives considered

- **Scribe as a normal dependency, with its own /docs route:** simplest, but ships a development tool and its routes to the live server.
- **Static files in `public/docs`:** served by nginx directly, but its relative links break on `/docs` without a trailing slash, and nginx's handling of the folder differs between the image and `php artisan serve`.
- **Example answers from Scribe's response calls:** richer docs, but generated by sending real requests to the local API, so the result depends on local data and requests can change it.

## Consequences

- After changing an endpoint, run `composer docs` and commit the result; nothing checks automatically that the docs are up to date.
- The docs show requests and fields but no example answers; adding `@response` tags to an endpoint adds one.
- The docs page loads two scripts and a stylesheet from public CDNs (jsDelivr, unpkg, cdnjs) and fonts from Google, allowed only on that page.
